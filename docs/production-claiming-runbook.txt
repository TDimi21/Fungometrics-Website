2. BACKUP AND RESTORE VERIFICATION — BEFORE MIGRATION APPROVAL
Use Plesk Backup Manager for a full subscription backup including database,
configuration, uploaded files and application data. Use encrypted/private backup
storage outside the web root and an access-controlled off-host copy. Preserve
.env, APP_KEY, previous release artifact, public/build, worker/cron configuration.
Do not put the backup in Git. Record backup ID, timestamp and retention owner.

Also prepare a database-specific logical dump with a compatible MariaDB client.
Have the DBA create a private client defaults file through an editor (NOT shell
arguments/history), e.g. ~/.config/fmtrx/production-backup.cnf with [client], host,
port/socket, user and password. Give only required backup permissions. Retain
existing connection/TLS settings. Do not source .env as shell code.
  umask 077
  export FMTRX_DB_CNF="$HOME/.config/fmtrx/production-backup.cnf"
  chmod 600 "$FMTRX_DB_CNF"
Set the VERIFIED database name, not a guess:
  export FMTRX_DB='REPLACE_WITH_VERIFIED_DATABASE_NAME'
  export FMTRX_BACKUP_DIR="$HOME/fmtrx-private-backups/$(date -u +%Y%m%dT%H%M%SZ)"
  mkdir -p "$FMTRX_BACKUP_DIR"
  chmod 700 "$FMTRX_BACKUP_DIR"
  mysql --defaults-extra-file="$FMTRX_DB_CNF" --database="$FMTRX_DB" -e 'SELECT VERSION(),DATABASE();'
STOP if this does not identify exactly the intended database/server.

For InnoDB-only base tables, with NO concurrent schema changes, use:
  mysqldump --defaults-extra-file="$FMTRX_DB_CNF" --single-transaction --quick --routines --events --triggers --hex-blob --default-character-set=utf8mb4 "$FMTRX_DB" > "$FMTRX_BACKUP_DIR/database.sql"
Immediately check success (before running another command):
  echo $?
Then:
  test -s "$FMTRX_BACKUP_DIR/database.sql"
  gzip -k "$FMTRX_BACKUP_DIR/database.sql"
  gzip -t "$FMTRX_BACKUP_DIR/database.sql.gz"
  sha256sum "$FMTRX_BACKUP_DIR/database.sql.gz" > "$FMTRX_BACKUP_DIR/database.sql.gz.sha256"
  cd "$FMTRX_BACKUP_DIR"
  sha256sum -c database.sql.gz.sha256
  cd "$FMTRX_ROOT"
STOP on any dump error/privilege warning. A nonempty file/checksum alone does NOT
prove recoverability. Avoid --force. Do not omit routines/events to hide errors.
If any base tables are nontransactional, STOP this backup recipe: DBA must
coordinate a consistent locked/physical backup with an approved write outage.
Single-transaction does not make MyISAM consistent and does not protect against
concurrent DDL. For exact before/after count comparison, quiesce writes from all
web/API/worker/import sources during the snapshot; otherwise counts can drift.

Restore rehearsal must run on an ISOLATED MariaDB 10.1.48 server with event
scheduler OFF, no app workers, no production mail keys, and no network path to
production services. Never import this dump into a different schema on the live
server: views/routines/events may contain schema-qualified references/definers.
Have DBA provision a blank same-name schema and compatible definers on isolated
server, and a separate restore.cnf pointing ONLY there. Verify identity first:
  mysql --defaults-extra-file=/private/restore.cnf -e 'SELECT @@hostname,VERSION(),@@event_scheduler;'
STOP unless operator confirms isolation and event_scheduler=OFF.
After copying the protected dump and checking its SHA256 on that host:
  mysql --defaults-extra-file=/private/restore.cnf --database="$FMTRX_DB" < /private/verified/database.sql
  echo $?
  mysqlcheck --defaults-extra-file=/private/restore.cnf --check "$FMTRX_DB"
Verify full table/view/routine/trigger/event inventory, migration rows, exact row
counts at snapshot, and sampled original player UUID/foreign-key relationships.
Examples (read only, on restore and matching frozen source snapshot):

Use actual table names from inventory; do not assume a guessed name exists.

7. SAFE CACHED-CONFIG CHECK (READ ONLY, NO TINKER DEPENDENCY)
From application root, using verified PHP. This bootstraps existing application
config, prints only allowlisted nonsecret values and key-presence boolean, and
fails if the pre-pilot OFF configuration is not loaded. Never dump all config.
  "$FMTRX_PHP" <<'PHP'
<?php
require 'vendor/autoload.php';
$app = require 'bootstrap/app.php';
$app->make(Illuminate\Contracts\Console\Kernel::class)->bootstrap();
$c = config('communications', []);
$gates = array_merge(array_intersect_key($c, array_flip(['enabled','send_enabled','weekly_enabled','invitations_enabled'])), $c['categories'] ?? []);
$off = count($gates) === 12 && !array_filter($gates);
$queue = config('queue.default');
$summary = [
  'communications_off' => $off,
  'pilot_mode' => $c['pilot_mode'] ?? null,
  'allowlist_count' => count($c['pilot_allowlist'] ?? []),
  'frontend_url' => $c['frontend_url'] ?? null,
  'queue' => $queue,
  'queue_driver' => config("queue.connections.$queue.driver"),
  'retry_after' => config("queue.connections.$queue.retry_after"),
  'cache' => config('cache.default'),
  'mail_default' => config('mail.default'),
  'sender' => config('mail.from.address'),
  'sender_name' => config('mail.from.name'),
  'resend_key_present' => filled(config('resend.api_key')),
  'app_debug' => config('app.debug'),
];
echo json_encode($summary, JSON_PRETTY_PRINT).PHP_EOL;
$ok = $off && ($c['pilot_mode'] ?? false) && empty($c['pilot_allowlist'])
  && ($c['frontend_url'] ?? '') === 'https://app.fmtrx.com'
  && $summary['queue_driver'] === 'database' && $summary['retry_after'] > 60
  && !in_array($summary['cache'], ['array', null], true)
  && $summary['mail_default'] === 'resend'
  && $summary['sender'] === 'notifications@mail.fmtrx.com'
  && $summary['sender_name'] === 'FMTRX' && $summary['resend_key_present']
  && !$summary['app_debug'];
exit($ok ? 0 : 1);
