fmtrx:communications-status previously returned success even with missing or old
execution evidence. It now supports --check and --expect-probe=UUID, returning
failure for missing, malformed, future, stale (>180 seconds), mismatched evidence,
or unsupported queue/cache configuration. Probe enqueue and check are separate.
The command does not print keys, recipients, payloads or invitation tokens.
Default inspection remains read-only; --probe-worker queues only a harmless job.
Neither a passing check nor a timestamp proves unattended execution if an operator
has manually run the worker/scheduler. Never use Run Now during verification.
