SHARED API CONTRACT
Additive planner_contract_version: "2.0" on unified responses, preserving existing
legacy identifiers and request shapes. Unified plan payload contains:
version, owner, team, scheduled_date, source, blocks/buckets, assignment,
progress, completion, actual_results, readiness, post_training, alert_review,
schedule_adjustments, session_links, update_status and settings.
Execution metadata is server-derived: COMPLETE / LOG / LAUNCH_SESSION.
POST progress supports version and assignment_version; mismatches return 409.
Legacy requests without a version remain accepted for backward compatibility;
they do not provide the same stale-write protection as v2 callers.

New routes under existing authentication/entitlement groups:
GET  /api/coach/planner/day?team_id=...&date=...&player_id=... (optional player)
GET  /api/player/planner/day?date=... (own published assignments only)
POST /api/coach/daily-plans/{id}/schedule-adjustment
POST /api/player/daily-plans/{id}/schedule-adjustment
POST /api/coach/daily-plans/{id}/prescription-adjustment
POST /api/coach/daily-plans/{id}/alert-review
Existing daily-plan, template, program, progress and training routes extended.
POST /api/training accepts planner_plan_id/planner_item_id to validate and reuse
one linked canonical session on retries. Player, team and session type checked.
Program publish accepts entry_ids, selected player_ids and explicit resolutions.
No subscription gate was removed or new paid restriction introduced.

Full assignment conflict/preview workflow across both clients is incomplete.

Cross-device autosave: PARTIAL. Program drafts debounce to server with version
checks and local recovery. Daily-plan draft saves share versions/IDs across
web/app but not every daily/template/native editor autosaves. Results save
explicitly with pending local persistence. Real two-device UI walkthrough pending.

Linked sessions: registry covers bullpen, long_toss, weighted_ball, exit_velocity,
cage, live_ab, strength, assessment. Existing scoring tables reused.
Web and native direct canonical start/retry/return implemented for bullpen/LT/WB/EV.
Native launches use the existing PracticeStack resume engines and shared EndPractice
completion; returning refreshes canonical completion while preserving pending notes.
Cage/Live AB still need normal setup and manual linking. Strength logs directly;
assessment capture handoff remains incomplete. Registry coverage is not being
reported as fully implemented launch coverage.

Quick Throw Logger: IMPLEMENTED counts, weight, intent, timestamps and item notes.
Web category selection supports warm-up/catch-play/flat-ground/other. Native quick
entries currently default to warm-up; richer category/edit controls remain.

Daily Throw Ledger: IMPLEMENTED derived read model, not a new measurements table.
Combines scoped canonical pitch/LT/WB rows with quick counts, suppressing quick
counts for the same linked item. Tested example: 20 quick warm-up throws +
28 canonical long-toss records = 48 total throws; stale retry returns 409 and
still totals 48. Canonical observed rows remain single records.
Volume categories are not represented as equal-intensity or medical workload.

Strength: IMPLEMENTED set weight/reps/RPE/completion, volume/top-set summary,
existing fitness history and edit audit. Observed single reps update explicitly
mapped max fields; no fabricated estimated 1RM. Tested 100x5 + 110x3 = 830 lb
volume, one fitness row, audited correction, no inferred back-squat max.

Pre-training readiness: shared server weighting, alerts and display; program
session start requires a saved check-in. Some authoring-policy controls remain.
Post-training check-in: separate effort/fatigue/arm fatigue/soreness/pain/notes;
required numeric completion answers when policy enabled.
Coach alerts: arms >=7, overall fatigue >=8, pain flag; team-coach view/review,
actor/time/action, version checks. No automatic workout change or diagnosis.

Conflict merge: backend detects overlapping canonical types/strength. Web PROGRAM
publication offers merge/keep-existing/replace/move; requires explicit decision and
current versions. Merge retains source programs and exact merged prescriptions
with one canonical launcher. Recorded results cannot be merged/replaced.
Quick assignment and native publishing still lack the complete choice UI and
report the conflict for resolution instead. This is a release-blocking gap.

Missed workout: per-player shift or same-program replace, transactional audit,
request retry idempotency, canonical conflict rejection, no master/teammate change.
Beyond-end extension is recorded. Standalone replace semantics and all schedule
resolution/edit affordances require further work.
