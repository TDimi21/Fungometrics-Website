FMTRX legacy coach invitation compatibility fix — 2026-10-16

Confirmed existing main branch, initially clean working tree. No branches or
worktrees created. No production access or configuration changes.

Cause and correction
Legacy self-registered coaches authenticate with users.status=0. The existing
acting-coach authorization already accommodates this, but recipient checks
still rejected them during issuance, acceptance, and shared delivery/resend
eligibility. Removed those three recipient-status predicates only.

Changed implementation
app/Services/Communications/InvitationService.php
app/Services/Communications/InvitationEligibility.php

Protections retained
Soft-deleted recipients remain rejected; default User queries exclude them at
acceptance. Recipient must remain a coach with the matching invitation email.
Only an authorized team head coach can invite another coach; authorization is
rechecked during delivery and acceptance. Duplicate email-account detection,
existing-account password/authenticated ownership, expiring single-use tokens,
verified-email recording, coach seat limits and assistant-only membership
creation remain unchanged. No existing account status or password is rewritten
when an existing password-bearing coach accepts. Player invitation behavior
and age restrictions are unchanged. No sending switches were changed.
